# Пользователи и модули

В режиме `RONIX_AUTH_MODE=authentik` Caddy проверяет вход через Authentik,
а Ronix связывает данные с неизменным `X-Authentik-Uid`. Логин и отображаемое
имя могут меняться. Администратор назначается явно по UID, а не по имени
или порядку регистрации.

Панель `/admin` позволяет выдавать модули `chat`, `learning`, `development`
и `outline`, назначать администраторов и отключать аккаунты. Новый пользователь
появляется после первого входа и не получает модулей автоматически. Изменение
прав останавливает его окружение и активные задачи. Последнего действующего
администратора нельзя отключить. Роль администратора не открывает чужую переписку.

## Хранение и запуск

Каждому пользователю принадлежит каталог `RONIX_USERS_DIR/<internal-uuid>`:
`data` (SQLite), `projects`, `codex` (история Codex), `home`. Реестр прав лежит
отдельно в `RONIX_ACCESS_DIR`. Backend и Codex запускаются вместе в bubblewrap:
видны только файлы приложения, системные библиотеки и каталог этого пользователя.
Файл `.env`, родительский реестр прав и каталоги других пользователей не монтируются.
Черновики браузера также разделены по внутреннему UUID.

Нужны Linux, bubblewrap, Node.js 22.5+ и рабочий установленный Codex.
`RONIX_SHARED_AUTH_FILE` указывает на общий `auth.json`, который копируется
в личное окружение при запуске. Аккаунт и лимиты Codex общие; после повторного
входа в исходный аккаунт следует перезапустить службу, чтобы обновить копии.

`RONIX_OUTLINE_CONFIG` — отдельный TOML-фрагмент `[mcp_servers.outline]` с
`bearer_token_env_var = "OUTLINE_API_KEY"`. Он и переменная передаются только
пользователям с модулем Outline. Доступ к документам определяется правами общего
ключа Outline, а не персональными аккаунтами Authentik. Отзыв модуля прекращает
передачу ключа в новые окружения, но не отзывает ранее скопированный пользователем
ключ; для этого нужно заменить ключ в Outline.

В чате создание и редактирование документов через Outline MCP выполняется по
явному запросу пользователя без подключения файлового проекта и без модуля
`development`. Режим «Чат» (`ask`) оставляет локальные файлы только для чтения;
«Изменить файлы» (`act`) требует модуля разработки и подключённого проекта.
Эти режимы не заменяют права ключа Outline. Подтверждения MCP показываются в чате.

Администратор назначает каждому пользователю модель чата в панели пользователей.
«По умолчанию сервиса» использует текущую модель по умолчанию из списка Codex.
Обычный пользователь не может сменить модель чата через интерфейс или API;
назначение применяется также к следующему сообщению в существующем чате.
Смена назначения перезапускает пользовательское окружение и останавливает его
активные задачи. Недоступная назначенная модель вызывает ошибку без подмены.
Администраторы свободно выбирают модель собственных чатов. Настройка не ограничивает
модели учебных и проектных сессий.

## Граница доверия прокси

Gateway должен слушать только loopback. Задайте случайный `RONIX_PROXY_SECRET`
длиной не менее 32 символов и `RONIX_TRUSTED_PROXIES=127.0.0.1,::1`. Caddy обязан
удалять входящие `X-Authentik-*` и `X-Ronix-Proxy-Secret` перед `forward_auth`,
копировать идентичность из ответа Authentik и добавлять секрет только при передаче
запроса в Ronix. Храните конфигурацию с секретом вне пользовательских окружений.

Сеть сервера общая (`--share-net`); это изоляция файлов и процессов, а не отдельная
виртуальная машина. Не открывайте на localhost или Docker-адресах служебные API
без аутентификации. В частности, Caddy admin API должен слушать закрытый Unix-сокет
в каталоге caddy с режимом 0700, а не TCP-порт 2019. Не запускайте Caddy с
`--environ`, если секреты передаются через окружение. Для полностью недоверенных
арендаторов нужны отдельная сетевая изоляция и отдельные сервисные учётные данные.

## Перенос существующего владельца

Перед переносом сохраните конфигурацию и приложение, убедитесь, что задач нет,
и остановите службу. Новые `RONIX_USERS_DIR` и `RONIX_ACCESS_DIR` должны находиться
вне старого `DATA_DIR`. Задайте `RONIX_OWNER_SUBJECT`, `RONIX_OWNER_USERNAME`,
`RONIX_OWNER_CODEX_HOME`, а также `RONIX_ADMIN_SUBJECTS` с тем же UID. Запустите
`node dist/src/migrate-owner.js` от имени пользователя службы с этими переменными.
Команда копирует старую БД и историю Codex, сохраняет исходники и отказывается
перезаписывать уже существующие данные владельца.

При запуске только владелец получает старые `PROJECT_ROOTS` и путь-алиас
`RONIX_OWNER_CODEX_HOME`, чтобы сохранённые пути проектов и истории оставались
действительными. Не указывайте здесь `/`, каталоги реестра прав или других
пользователей. Новые аккаунты получают собственный пустой каталог проектов.

После включения проверьте `/api/me`, старые сессии владельца, список моделей,
запрет запросов без прокси-секрета, вход через Authentik и панель `/admin`.
При откате верните прежние приложение, конфигурацию прокси и службы; исходная БД
остаётся доступной. Изменения, сделанные после перехода в новой БД, автоматически
в старую БД не переносятся.
